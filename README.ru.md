# Componenta Queue

Независимая PHP-библиотека очередей: неизменяемые сообщения, явное владение
доставкой, ограниченные повторы и сохранение неудачных сообщений для разбора и
повторного запуска. Ядро не зависит от Componenta App, CQRS, контейнера или ORM.

[English documentation](README.md)

## Пакеты

| Пакет | Назначение |
| --- | --- |
| `componenta/queue` | Сообщения, кодек, Worker, обработчики, retry, очередь в памяти и тестовый publisher |
| [componenta/queue-cycle](https://github.com/componenta/queue-cycle) | Постоянная очередь на PostgreSQL через Cycle Database |
| [componenta/queue-console](https://github.com/componenta/queue-console) | Цикл обработки, лимиты процесса, сигналы и управление ошибками |
| [componenta/queue-app](https://github.com/componenta/queue-app) | Регистрация в App, подготовленные карты и отдельная область сервисов сообщения |
| [componenta/cqrs-queue](https://github.com/componenta/cqrs-queue) | Публикация команд и синхронное выполнение через CQRS |

У каждого пакета отдельный репозиторий и Composer-манифест. Ядро устанавливается
без базы данных, консольного приложения или фреймворка.

## Запуск

Требуется PHP `^8.5.13`. В рабочей копии репозитория:

```sh
composer install
composer test
composer analyse
composer cs:check
php examples/basic.php
```

Последняя команда запускает полный пример публикации, выбора обработчика и
подтверждения сообщения через очередь в памяти. Тесты PostgreSQL, схема и
настройки постоянного хранения находятся в репозитории
[queue-cycle](https://github.com/componenta/queue-cycle).
Выполненные проверки описаны в [отчёте о реализации](docs/implementation.md).

## Основные решения

Идентификатор сообщения принадлежит приложению и сохраняется при повторах.
Идентификатор сообщения не даёт права подтвердить доставку: для этого адаптер
создаёт отдельную краткоживущую возможность. Обработчик получает сообщение,
метаданные и возможность продлить аренду; подтверждением управляет Worker.

Обработчик сначала завершает работу, затем Worker подтверждает сообщение.
Ошибка подтверждения не превращается в ошибку обработчика и не приводит к
другому действию над доставкой. Любая ошибка продления аренды запрещает
последующее подтверждение, retry или помещение в карантин в том же шаге,
даже если обработчик поймал исключение. При инфраструктурной ошибке Worker
закрывает сессию; для восстановления создаётся новая.

Повторы ограничиваются явной политикой. Задержка хранится в очереди, Worker не
спит ради retry. Число запланированных повторов отделено от числа выдач сообщения;
выдача, потерянная при падении процесса, тоже расходует бюджет доставок.

Кодек использует фиксированный JSON-конверт и канонический base64 для двоичного
тела. Он отвергает дублирующиеся JSON-поля, неподдерживаемые версии и превышение
явных ограничений. Повреждённый конверт сохраняется в исходном виде и не запускает
обработчик. PHP-объекты и имена классов не десериализуются из сообщения.

История ошибок поддерживает ограниченные страницы, просмотр исходных байтов,
повторный запуск и окончательный отказ. Повторный запуск одной ошибки с теми же
параметрами идемпотентен в пределах срока хранения истории. По умолчанию
диагностика содержит категорию и класс ошибки, без текста исключения, трассировки
и содержимого сообщения.

PostgreSQL-адаптер выполняет переходы состояния атомарно, использует write-соединение
и проверяет право владения по времени базы после получения блокировки. Явный
`TransactionalPublisher::stage()` добавляет сообщение в транзакцию бизнес-операции,
не подтверждая эту транзакцию самостоятельно.

Очередь в памяти сохраняет состояние сообщений, если опрос не смог получить
время или подготовить следующую доставку. Сообщения с исчерпанным бюджетом
попадают в историю ошибок только после успешной подготовки всего опроса.
Поэтому отказ, означающий отсутствие эффекта, не оставляет частичных изменений.

Библиотека допускает повторную доставку и не обещает ровно однократный внешний
эффект. Идемпотентность прикладного действия, inbox или ключ внешнего API остаются
ответственностью приложения. Управление процессом, сигналами и интеграция с App/CQRS
описаны отдельно.
